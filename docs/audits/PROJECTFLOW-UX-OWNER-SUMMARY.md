# ProjectFlow — סיכום בעלים (UX / מבנה מידע)

**תאריך:** 28 אוגוסט 2026  
**סוג:** ביקורת בלבד — לא בוצעו שינויים במוצר  
**מקור:** מסכים אמיתיים בפרודקשן (ארגון מתח ח.י) + מיפוי קוד ליכולות מוסתרות  

---

## למה האתר מרגיש מסורבל?

ProjectFlow צבר הרבה יכולות טובות — אבל **אותה סיפור כלכלי מספרים פעמיים ושלוש** במקומות שונים.

בעל עסק שרוצה לדעת "כמה הרווחתי?" נתקל ב:

- לוח בקרה עם עשרות מספרים
- דוחות עם **אותם** מספרים שוב, עם הסברים ארוכים
- בכל פרויקט — **סקירה** שכבר נראית כמו דוח, ועוד לשונית **כספים** שחוזרת על חלק גדול מהמידע
- מונחים פנימיים: "עלות בפועל", "התחייבויות", "הוצאות כלליות שלא הוקצו", "עלות משותפת", "Reversal"

התפריט הראשי מציג **לוח בקרה, היום, פרויקטים, עבודות, הוצאות** — ואז עוד **9 קבוצות נפתחות** (לקוחות, אנשים, רכש, כסף, שטח, דוחות, מתקדם…). זה נכון טכנית, אבל לבעל עסק זה נשמע כמו מערכת ERP, לא כמו "ניהול פרויקטים והכסף".

## איפה הכפילויות הגדולות?

| מה חוזר על עצמו | איפה רואים את זה |
|-----------------|------------------|
| **שווי / חוזה / רווח** | לוח בקרה, דוחות, כותרת פרויקט, סקירת פרויקט, כספי פרויקט |
| **חיוב / גבייה / יתרה** | לוח בקרה (פעמיים "יתרה פתוחה"), דוחות, כספי פרויקט, לקוח, חיובים גלובליים |
| **עלות בפועל / תחזית** | לוח בקרה, דוחות (שכבת עלות שלמה), סקירה + כספים בפרויקט |
| **הוצאות** | רשימת הוצאות, מסך "הוצאות כלליות" (מוסתר אבל קיים), פרויקט, ספק, AP |
| **ספקים / קבלני משנה** | ספקים, קבלנות משנה, רכש, חשבוניות ספק, כרטיס ספק בפרויקט |
| **שעות / צוות** | אנשים, שעות, פרויקט (צוות + שעות), דוחות |
| **דברים לטיפול** | לוח בקרה ("יש דבר לבדיקה"), היום, התראות |

**הכלל שנשבר:** במקום "מספר אחד + קישור לפרט", יש **לוח משנה שלם** בכל מקום.

## אילו מסכים הכי בעייתיים?

1. **דוחות** — עמוד ענק: מסחרי, תזרים, עלות, רווחיות, ניהול, עשרות PDF. זה דוח מלא שמוצג כיעד ניווט ראשי.
2. **סקירת פרויקט (Overview)** — 15+ פאנלים: שטח, טפסים, checklist, אזהרות, לוח זמנים, חוזה, תמונה כספית, פירוט עלות, אבני דרך, היסטוריה, חוזים, סגירה, אחריות, הודעות, קבלנים.
3. **כספים בפרויקט** — שוב פירוט עלות, חיוב, תזרים, ספקים — חופף לסקירה ולדוחות.
4. **לוח בקרה** — הרבה KPI בלי טבלת פרויקטים פשוטה (ערך \| עלות \| רווח \| רווחיות).
5. **פרטי הוצאה** — מחזור חיים מורכב (טיוטה, אישור, ביטול, היפוך, תיקון, שרשרת תיקונים) חשוף למשתמש.
6. **כרטיס ספק** — AP, הסכמים, ביצועים, מסמכים, תקשורת — הכל בדף אחד.
7. **הגדרות** — 20+ יעדים; קטגוריות עלות מפוזרות בין "קטגוריות עלות", "קטלוגים", "מה יוצג".

## מה לדעתי המבנה הנכון?

### ניווט ראשי (5–6 יעדים)

```
לוח בקרה
היום          ← מה דורש טיפול
פרויקטים      ← מרכז העבודה
הוצאות        ← רישום עלויות
לקוחות        ← (אופציונלי לפי סוג עסק)
עוד ▾         ← אנשים, רכש, דוחות, הגדרות
```

**לא** בתפריט הראשי: חשבוניות ספק, סגירת חודש, GCM, RFQ, מלאי FIFO, API — נשארים במנוע, לא במסך הבית.

### פרויקט — 5 אזורים

```
סקירה     ← סטטוס, תאריכים, 3–4 מספרים, מה דורש טיפול
כספים     ← חוזה, עלות, רווח, חיוב — המקור המלא
עבודה     ← צוות, שעות, BOQ, שינויים, לוח זמנים, שטח
מסמכים    ← קבצים, חוזים, טפסים
פרטים     ← הגדרות הפרויקט, סגירה, אחריות
```

17 לשוניות נפרדות → **5 אזורים עם תת-ניווט פנימי**.

### לוח בקרה — סיפור אחד

1. **שורה עליונה:** ערך עבודה \| עלות בפועל \| רווח \| רווחיות (%)
2. **טבלת פרויקטים:** שם \| ערך \| עלות \| רווח \| %
3. **דורש טיפול** (קצר)
4. **פעילות אחרונה**
5. **פעולות מהירות** (הוצאה, פרויקט)

בלי לשכפל את כל דף הדוחות.

### הוצאה — מודל פשוט למשתמש

**יצירה:** ספק, קטגוריה, פרויקט/כללי, סכום, מע״מ, תאריך, תיאור, מסמך → **שמירה**

**אחר כך:** עריכה / ביטול (כשמותר)

מאחורי הקלעים נשמרים: אישור, תיקון, היפוך, שרשרת — **במסך מתקדם**, לא בכפתורים ראשיים.

### הגדרות — 3 קבוצות

```
העסק שלי     ← פרטים, מיתוג, מס, מספור, משתמשים
איך עובדים   ← יכולות, קטגוריות עלות, אישורים, תבניות
מתקדם        ← שדות מותאמים, API, פעילות, בנק, אינטגרציות
```

## מה צריך להישאר?

- מנוע כלכלי מלא (חוזה, BOQ, AP, התחייבויות, GCM, סגירת חודש)
- פרויקט כמרכז — אבל **פשוט יותר מבחוץ**
- הוצאות + חיוב + גבייה — **בנתיב ברור**
- דוחות PDF — **מתוך** פרויקט / דוחות, לא כל מסך בנפרד
- הרשאות ורב-ארגוניות

---

## מה צריך לעבור פנימה / למתקדם?

| היום בולט מדי | לאן |
|--------------|-----|
| סגירת חודש | הגדרות → מתקדם / הנהלת חשבונות |
| חשבוניות ספק (AP) | רכש → ספקים (לא ניווט ראשי) |
| הוצאות כלליות (overhead) | נבלע בהוצאות — דף נפרד מיותר |
| RFQ, מלאי, FIFO | רכש → מתקדם |
| טיוטות חוזרות | בתוך הוצאות / חיוב |
| CRM / מכירות | לפני-פרויקט — לא ליד פרויקטים פעילים |
| תצוגת חוויה (פרופילים) | כלי פיתוח — לא לבעלים |
| Reversal / correction chain | היסטוריה מתקדמת בהוצאה |

---

## מה לא צריך להיות מול המשתמש בכלל?

- מושגי מנוע: GCM, allocation atoms, cost family, committed vs actual (כמונחים)
- הסברים ארוכים על "מה כלול / לא כלול" בכל KPI (פעם אחת בהגדרות / עזרה)
- שכבת "סביבת עבודה" עם 20 קישורים החוצה מהפרויקט
- כפילות יתרה פתוחה / התחייבויות באותו מסך

---

## איך ייראה ProjectFlow אחרי ניקוי נכון?

**בעל עסק נכנס → תוך 10 שניות:**

- כמה שווה העבודה שלי
- כמה עלתה לי בפועל
- כמה נשאר לי
- איזה פרויקט דורש טיפול

**נכנס לפרויקט → רואה:**

- סקירה קצרה (לא 15 כרטיסים)
- כפתור "כספים" לכל הפירוט
- "עבודה" לצוות/BOQ/שינויים
- לא 17 לשוניות

**רושם הכללי:** מוצר שמדבר **תוצאות ותהליכים**, לא ארכיטקטורת חשבונאות.
