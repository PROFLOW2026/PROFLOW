## 5. מה מומש (בתוך התוכנית בלבד)

1. **מזהה שורה.** `legendRowId` מ-`fileId` + `signature` + מיקום + טקסט. נקודות מקבלות `legendRowIds[]`. אין `legendKey = signature` על זיהוי DWG.
2. **סתירה / אי־ודאות.** אין `typeKey` אוטומטי; ספרייה ו-`geometryHash` לא עוקפים. אישור ידני רק לנקודות שנבחרו.
3. **קליטה.** `ingestWorkerResult` כותב ל-`takeoff_legend_entries` הקיימת. `result_stats` JSONB מקבל `workerBuild`, `engineVersions`, ומדדי סעיף 4. ניתוח ישן בלי השדות נטען כמקרא ריק / «לא ידוע».
4. **ספרייה.** `save_legend` לפי hash של הטקסט המנורמל, לא לפי שם בלוק או מזהה שורה. שמירה דורשת `takeoff.library.manage`. DWG אוטומטי רק עם `geometryHash` זהה.
5. **עברית כללית.** `נקודה ל־X` (מילה אחת בסוף בלבד); `מפסק מאור` למשפחת המפסקים; `מפסק ביניים` נוסף לקטלוג לצד `מפסח ביניים`. אין מילת «פנדל». אין מילה אחת כסוג אלא אם היא כל התיאור.
6. **שלושה משטחים.** אותו UI / view / resolver. סניטציית מקרא לקבלן בלי נתיבים. גישה רק עם `takeoff.view` + מענק.
