# מסעות משתמש ליבה — ProjectFlow

**תאריך:** 2026-08-09 · **ביקורת בלבד**  
עברית פשוטה. מוצר מחובר בלבד.

---

## FLOW 1 — התחלה: עסק → לקוח → פרויקט → חוזה

**מה המשתמש רוצה:** להתחיל לעבוד על עבודה עם לקוח וסכום חוזה.

**זרימה נוכחית (תמצית):**  
הרשמה → הקמת עסק (onboarding) → (אופציונלי לקוח) → פרויקט חדש → פרטי פרויקט / חוזה.

**חיכוך:**  
- אחרי ההתחלה יש הרבה מסכים ומודולים מסביב.  
- «סכום חוזה» ו«שווי חוזה» מופיעים בשתי מילים.  
- Change Order באנגלית בנעילת סכום מקורי.

**מומלץ:**  
1 מסך התחלה ברור → לקוח (או דילוג) → פרויקט עם שם + סכום → סקירת פרויקט.  
בלי להסיח עם OCR / API / פורטל.

---

## FLOW 2 — פרויקט → הוצאה → רווחיות

**מה רוצה:** לרשום עלות ולראות איך זה משפיע על הפרויקט.

**זרימה נוכחית:**  
פרויקט → טאב הוצאות / FAB הוצאה → שמירה → טאב כספים / דוחות.

**חיכוך:**  
- כספים צפופים (כיסוי, AP, הסברים).  
- הרבה טאבים לפני שמגיעים למה שצריך.

**מומלץ:**  
הוספת הוצאה בכפתור ברור → חזרה לסיכום כספי קצר (בפועל / מחויב / יתרה) → «פרטים» למי שרוצה.

---

## FLOW 3 — צילום / העלאת קבלה → הוצאה  ⚠️

**מה רוצה:** לצלם קבלה ולקבל הוצאה.

**זרימה נוכחית:**  
הוצאות → קישור טקסט «צילום קבלה לחילוץ» → מסך OCR → צילום/העלאה → (בדרך כלל כשל stub) → או «טעינת מועמד לדוגמה» → אישור טיוטה.

**חיכוך (קריטי):**  
1. קשה לגלות את הקישור.  
2. השם לא מסביר מה יקרה.  
3. מסך מלא אזהרות טכניות (`OCR_PROVIDER_API_KEY`, stub).  
4. אין חילוץ אמיתי היום.  
5. «צילום» על מסמך רגיל ≠ OCR — מבלבל.

**מה עובד היום:** ממשק בדיקה + טיוטת הוצאה אחרי אישור ידני/פיקסצ׳ר.  
**מה לא:** חילוץ אוטומטי אמיתי.

**המלצת מוצר (ליישום רק אחרי אישור):**  
- **להסתיר OCR מלקוח רגיל** עד ספק אמיתי, **או** להציג במפורש «עדיין לא זמין — הוסיפו הוצאה ידנית».  
- בינתיים: «הוספת הוצאה» + צירוף תמונה למסמך.  
- אם נשאר גלוי: כפתור «הוצאה מצילום קבלה» — בלי מילים טכניות.

**«צילום קבלה לחילוץ» — מקובל?**  
**לא.** לבעל עסק זה נשמע כמו שלב מערכת, לא כמו משימה.

## FLOW 4 — בקשת שינוי → אישור → חוזה מעודכן

**מה רוצה:** להוסיף/להפחית מהחוזה בצורה מבוקרת.

**זרימה נוכחית:**  
שינויים → חדש → תמחור → אישור.

**חיכוך:**  
- ריק/אזהרות צפופים.  
- בסך הכל המושג נכון וחשוב.

**מומלץ:**  
שמירה על התהליך; קיצור טקסטים; כותרות קצרות: טיוטה → ממתין → מאושר.

---

## FLOW 5 — חיוב → תשלום → יתרה

**מה רוצה:** לדעת כמה לגבות וכמה שולם.

**זרימה נוכחית:**  
חיובים → חיוב חדש / תשלום → פירוט.

**חיכוך:**  
- חשוב להבהיר שזה **לא** חשבונית מס (כבר כתוב — לשמור בקצרה).  
- בלבול אפשרי בין «חשבון» ל«חשבונית».

**מומלץ:**  
מילון אחיד; מסך אחד: נותר לגבייה.

---

## FLOW 6 — עובד → שעות → עלות עבודה

**מה רוצה:** לרשום שעות שמשפיעות על עלות.

**זרימה נוכחית:**  
כוח אדם → עובדים / שעות → דיווח.

**חיכוך:** נמוך יחסית. «העמסת מעסיק» למתקדמים.

**מומלץ:** להשאיר פשוט; מתקדם מאחורי פרטים.

---

## FLOW 7 — ספק → רכש → עלות מחויבת → AP

**מה רוצה:** להתחייב לספק בלי לבלבל עם הוצאה.

**זרימה נוכחית:**  
ספק → רכש/RFQ → הזמנה → (מתקדם) חשבון ספק.

**חיכוך:**  
- מתחייב מול מחויב.  
- טאב «התאמת AP».  
- הרבה שלבים למי שלא צריך AP.

**מומלץ:**  
CORE: ספק + הזמנת רכש.  
ADVANCED: חשבונות ספקים.  
מילה אחת ל־committed.
