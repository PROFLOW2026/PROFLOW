# ביקורת פישוט מוצר — ProjectFlow (מוצר מחובר בלבד)

**תאריך:** 2026-08-09  
**סוג:** ביקורת בלבד — ללא שינוי קוד  
**היקף:** כל המסכים אחרי כניסה. **לא** כולל דף הבית הציבורי / שיווק.

---

## 1. סיכום מנהלים

ProjectFlow כבר עושה עבודה חזקה של אמת פיננסית (חוזה ≠ הוצאה ≠ רכש ≠ חיוב).  
הבעיה העיקרית כרגע אינה "חוסר יכולות" — אלא **יותר מדי טקסט, יותר מדי מונחים טכניים, ופעולות חשובות שנראות כמו קישור משני**.

הבעלים דיווח שמצא את «צילום קבלה לחילוץ» אחרי כ־20 דקות. זה לא באג נקודתי — זה סימן שמבנה המוצר והשפה לא מדברים בשפת לקוח עסקי.

**מספרים משוערים (מוצר מחובר):**

| מדד | כמות |
|-----|------|
| מסכים / נתיבים שנבדקו | **~75** |
| דליפות טכניות / פנימיות | **~28** |
| ניסוחים לא ברורים / ז'רגון | **~45** |
| בעיות גילוי פעולות | **~18** |
| מסכים עם עודף טקסט | **~16** |
| בעיות ניווט / מבנה מידע | **~12** |

## 2. הבעיות הגדולות ביותר

1. **שפת מפתחים על מסכי לקוח** (OCR עם `OCR_PROVIDER_API_KEY`, stub, מועמד לדוגמה; ייצוא עם `contracts:read`; צי רכב עם «מיגרציה 0011»).
2. **פעולות חשובות נראות כמו טקסט** ולא כמו כפתור (צילום קבלה בהוצאות).
3. **מסך OCR מבטיח חילוץ** בזמן שאין ספק אמיתי — והפעולה שעובדת היא «טעינת מועמד לדוגמה».
4. **יותר מדי יעדים בניווט** באותה רמת חשיבות (CORE ליד ADVANCED).
5. **מונחים כפולים** לאותו רעיון (מתחייב/מחויב, סכום חוזה/שווי חוזה, AP בעברית וגם באנגלית).
6. **CRM עם ניסוחים מוזרים** («נצח», «אבוד», «פרוספקט») וסדר ניווט הפוך למשפך מכירות.
7. **הגדרות שטוחות** (~15 פריטים) בלי הפרדה בין בסיסי / מתקדם / פנימי.
8. **הסברים ארוכים לפני העבודה** (פורטל, API, כספים/כיסוי, OCR).
9. **בלבול בין צילום מסמך לצילום לחילוץ** — שני דברים שונים במוצר.
10. **מסכים שלא עוברים מבחן 5 שניות** (OCR, פורטל, API, חלק מהדוחות הכספיים).

## 3. מסכים עם עודף טקסט

| מסך | בעיה |
|-----|------|
| `/documents/ocr-review` | כותרת + אזהרת ספק + פסקת יושר + מועמדים + מיפוי + מטא־דאטה |
| `/settings/portal` | חזרות רבות על «לא כותב אמת פיננסית» |
| `/settings/api` | פרוטוקול HTTP / Bearer בעמוד הגדרות |
| `/settings/custom-fields` | באנרים על קנוניות ודיווח |
| כספי פרויקט / דוחות | הסברי כיסוי ו־AP צפופים |
| שינויים — ריק | משפט אזהרה קשה לקריאה |
| חיובים — כותרת משנה | חשובה, אבל ארוכה לצד הרבה פעולות |

## 4. דליפת מידע טכני / פנימי

### HIGH (אסור שלקוח רגיל יראה)

| מחרוזת / נושא | איפה |
|---------------|------|
| `OCR_PROVIDER_API_KEY` | OCR |
| «ספק הבדיקה (stub)» / «מתאם ספק» | OCR |
| «טעינת מועמד לדוגמה» | OCR |
| provenance גולמי (`fixture`, `user_override`) | OCR UI |
| `contracts:read`, `project_profit:read`, `audit.read` | הערות ייצוא |
| «מיגרציה 0011» / עמודות סכמה | צי רכב |
| `GET /api/v1`, Bearer, cookie של Next | הגדרות API |
| scopes באנגלית גולמית | API |
| `portal_kind` + `vendorId` | פורטל |
| DSL רכיבי שכר (`pension=percent:…`) | קטלוג |
| `/setup` עם `.env` / Supabase | אם נגיש בפרודקשן |

### MEDIUM

AP כתווית ראשית, מטא־דאטה, מזהה נושא, גישה חתומה, מגבלה 50, Change Order באנגלית, UUID בטקסטים.

## 6. מורכבות ניווט

- Bottom nav: לוח בקרה / פרויקטים / הוצאות — **נכון**.
- «עוד» מכיל מודולים רבים באותה משקל ויזואלי.
- טאבי פרויקט ארוכים בעברית (גלילה אופקית).
- CRM: הזדמנויות לפני מתעניינים/לידים — הפוך למשפך.
- הגדרות: בלי קבוצות CORE / ADVANCED / מפתחים.

## 8. עקרונות פישוט מומלצים

1. **לקוח רואה משימה — לא ארכיטקטורה.**
2. **כפתור ראשי אחד ברור בכל מסך.**
3. **שורה אחת של הסבר, לא פסקה.**
4. **מתקדם מאחורי «פרטים נוספים» / הגדרות מתקדמות.**
5. **אסור משתני סביבה / stub / fixture בממשק לקוח.**
6. **פיצ'ר שלא עובד באמת — לא מוצג כפעולה ראשית (או מסומן כבדיקה).**
7. **אותו מושג = אותה מילה בכל המוצר.**
8. **CORE קטן; OPTIONAL לפי צורך; ADVANCED מוסתר כברירת מחדל.**
9. **אמת פיננסית נשארת — רק ההצגה מתפשטת.**
10. **עברית של בעל עסק ישראלי, לא תרגום מילולי מאנגלית.**

## 9. Top 20 תיקונים בעלי השפעה (ליישום רק אחרי אישור)

1. להסתיר או לסמן OCR כלא־זמין עד ספק אמיתי  
2. להסיר `OCR_PROVIDER_API_KEY` / stub / fixture מה־UI  
3. לשנות «צילום קבלה לחילוץ» לכפתור ברור (המלצת ניסוח בהמשך)  
4. להפריד ויזואלית בין «צילום מסמך» ל«הוצאה מצילום»  
5. לאחד מחויב/מתחייב  
6. להחליף תוויות AP באנגלית בעברית ברורה  
7. לתקן CRM: נצח/אבוד/פרוספקט  
8. לסדר ניווט CRM לפי משפך  
9. להסיר מפתחות הרשאה מייצוא  
10. להסיר טקסט מיגרציה מצי רכב  
11. לקצר יושר כספי ל־1 משפט + «למה?»  
12. לקבץ הגדרות ל־CORE / מתקדם / מפתחים  
13. להקטין פורטל ב־70% או להעביר ל־INTERNAL  
14. להעביר API ל«מפתחים»  
15. לפשט שדות מותאמים (בלי קנוניות/snake_case בכותרת)  
16. לאחד סכום חוזה / שווי חוזה  
17. לקצר ריק של שינויים  
18. לשנות טאב AP ל«חשבונות ספקים»  
19. להבהיר שחיוב ≠ חשבונית מס (קצר וקבוע)  
20. לבדוק FAB: רק פעולות שעובדות באמת

## 10. מה לא לשנות

- אמת פיננסית: חוזה / בפועל / מחויב / תחזית / מס לא רווח  
- הפרדה: הוצאה ≠ הזמנת רכש ≠ חיוב  
- שינוי מאושר מעדכן חוזה; טיוטה לא  
- התאמת AP לא יוצרת הוצאה  
- הרשאות ו־RLS  
- ערכי enum פנימיים בקוד (רק הצגה)  
- דף הבית הציבורי (סוכן אחר)
