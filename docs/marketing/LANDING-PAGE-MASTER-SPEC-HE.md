## 0. סקירת הבסיס הקיים (KEEP / REFINE / REMOVE / MERGE)

| מקור | החלטה | הערה |
|------|--------|------|
| Hero: «שליטה בפרויקט — מהחוזה ועד הרווח» | **KEEP** (מומלץ) | ברור ב־5 שניות; עסקי; לא באזז |
| תת־כותרת ארוכה | **REFINE** | לקצר; להשאיר את שרשרת הערך |
| שורת אמון «לא הנה״ח» | **KEEP** | קטנה מתחת ל־CTA |
| סקציית «הפתרון» נפרדת | **MERGE** → שאלות בעלים | פחות חזרה |
| בעיה (Excel/וואטסאפ) | **KEEP + REFINE** | פסקאות קצרות + 4 נקודות |
| איך זה עובד (זרימה) | **KEEP** | ויזואלי; ליבה של הסיפור |
| 8 בלוקי ערך ליבה | **MERGE** → 3–4 סקציות | סריקה; ליבה לפני מתקדם |
| מתקדם (CRM/רכש/שטח…) | **REFINE** | משני; כרטיסים קצרים; לא Hero |
| מובייל/PWA | **KEEP + REFINE** | התקנה כן; offline לא למכור |
| אבטחה | **REFINE** | קצר: צוות + הרשאות |
| למי זה | **KEEP** | להדגיש «לא רק קבלן ראשי» |
| FAQ | **KEEP + REFINE** | כנות על OCR/פורטל/Gantt |
| CTA «דברו איתנו» בסוף | **REFINE** | ראשי = התחילו עכשיו; משני = בקשו הדגמה (אופציונלי) |

### עקרון עמוד
**מוכרים ליבה קודם.** מודולים מתקדמים תומכים — לא שולטים.

## 1. Hero — בחירת כותרת

### 5 מועמדים לכותרת

1. **שליטה בפרויקט — מהחוזה ועד הרווח** ← מומלץ  
2. תדעו אם הפרויקט באמת מרוויח  
3. הפרויקט, העלויות והגבייה — במקום אחד  
4. מהחוזה המקורי — עד התשלום האחרון  
5. ניהול פרויקטים לעסקים שחיים מפרויקטים  

### 5 מועמדים לתת־כותרת

1. **מחברים פרויקט, חוזה, עלויות, שינויים, חיובים ותשלומים — כדי שתדעו מה באמת קורה.** ← מומלץ  
2. מקום אחד לחוזה, להוצאות, לשינויים ולגבייה — בלי לערבב חיוב עם תשלום.  
3. מערכת לעסקים מבוססי פרויקט: רואים כמה שווה, כמה עלה, מה חויב ומה שולם.  
4. פחות Excel ווואטסאפ. יותר שליטה על רווחיות הפרויקט.  
5. מתחילים פשוט. מעמיקים כשצריך. לא הנהלת חשבונות.  

### שילוב סופי מומלץ

| שדה | טקסט |
|-----|------|
| **H1** | שליטה בפרויקט — מהחוזה ועד הרווח |
| **תת־כותרת** | מחברים פרויקט, חוזה, עלויות, שינויים, חיובים ותשלומים — כדי שתדעו מה באמת קורה. |
| **CTA ראשי** | התחילו עכשיו |
| **CTA משני** | ראו איך זה עובד |
| **שורת אמון** | לא תוכנת הנהלת חשבונות. פשוטה בהתחלה — עמוקה כשצריך. |

**למה:** הכותרת מסבירה את המסע העסקי בלי טכנולוגיה. התת־כותרת מונה את הליבה. אין הבטחות foundation.

**שאלות ותשובות (סופי):**

**האם זו הנהלת חשבונות?**  
לא. ProjectFlow מנהלת את האמת העסקית של הפרויקט — חוזים, עלויות, שינויים, חיובים ותשלומים. רואה החשבון נשאר במקומו.

**האם חייבים להשתמש בכל המודולים?**  
לא. מדליקים רק מה שצריך. עסק קטן יכול לעבוד בפשטות.

**למי ProjectFlow מתאימה?**  
לעסקים מבוססי פרויקט: קבלנים, בעלי מקצוע, אדריכלים, מעצבים, יועצים ומנהלי פרויקטים — לא רק לקבלן ראשי.

**האם אפשר לעבוד מהטלפון?**  
כן. אותה מערכת ווב, מותאמת למובייל.

**האם אפשר להתקין כאפליקציה?**  
כן — מהדפדפן (מסך בית / אייקון). באנדרואיד לעיתים התקנה ישירה; ב־iOS דרך «הוסף למסך הבית». לא מחנות האפליקציות.

**מה ההבדל בין חיוב לתשלום?**  
חיוב = מה שנרשם כלפי הלקוח. תשלום = מה שבאמת התקבל.

**מה ההבדל בין התחייבות להוצאה?**  
התחייבות (למשל הזמנת רכש) = התחייבתם להוציא. הוצאה = העלות כבר קרתה.

**האם יש OCR שקורא חשבוניות אוטומטית?**  
לא כרגע. אפשר לצלם ולצרף מסמכים לרשומות. חילוץ אוטומטי חי עדיין אינו פעיל.

**האם יש פורטל לקוחות?**  
פורטל ציבורי עם התחברות ללקוח עדיין לא זמין.

**האם יש Gantt / נתיב קריטי?**  
יש תאריכים ואבני דרך בפרויקט — תזמון קל. לא Gantt מלא.
